## 1. Installing

Use `18-9L-6_ED-7-45-45_C-LS-Installer.exe` from the [Releases](../../releases) page.

1. Close the game.
2. Double-click the installer.
3. Pick your game folder — the one containing `Four Nights at the Burger Shop.exe`.
4. Wait for it to finish, then launch the game and press **F9**.

The installer bundles BepInEx 5.4.23.5. **You do not need to install BepInEx separately.**

It also cleans up the plugin file left behind by older versions — if you upgraded from
a version before the assembly name changed, you would otherwise end up with two plugins
sharing one GUID, and BepInEx does not define what happens then.

### Uninstalling

Run the same installer and choose uninstall, or run `卸载还原.ps1` from the game folder.
It works from a manifest written at install time, so it removes exactly what it added.

## 2. What gets installed, and where

| Path | Purpose |
| --- | --- |
| `winhttp.dll` / `doorstop_config.ini` / `.doorstop_version` | BepInEx 5.4.23.5 loader |
| `BepInEx\core\` | BepInEx itself |
| `BepInEx\plugins\` + the plugin assembly | The mod |
| `BepInEx\config\nesarf.burgershop.modder.cfg` | Settings, shared by the panel and the editor |
| `数值修改器.exe` | Standalone config editor |
| `使用说明.md` / `卸载还原.ps1` | This manual and the restore script |
| `burger-shop-mod.installed` | Install manifest |

The game's own files (`Four Nights at the Burger Shop.exe`, `*_Data\`, the DLC folder)
are never touched. `BepInEx\cache`, `LogOutput.log` and similar are created by BepInEx at
runtime and are removed on uninstall.

## 3. Two ways to use it

### 3.1 In-game panel (hotkey F9)

Press **F9** to toggle. The panel:

- has eight tabs (see section 4)
- can be collapsed so it does not block the scene
- scrolls — some tabs are longer than the screen
- every numeric control has **−** and **+** buttons beside the slider, for fine adjustment

Changes take effect immediately. They are written to the config file as you go.

### 3.2 External editor (`数值修改器.exe`)

A WinForms window with the same settings, laid out by category. Useful when the game is
not running, or when you want to paste exact numbers.

**Both can be open at the same time.** The config file has a revision counter and a lock;
the panel and the editor merge rather than overwrite each other (see section 8).

## 4. What you can change

The panel is **split by pose**, not by feature — the tab you want is the pose you are
currently interacting with. The first six are pose-specific; the last two are utilities.

| Tab | What it governs |
| --- | --- |
| **玩家** (Player) | Rates, quick toggles, burger stacks, ecstasy tremor, adaptation, drain caps, target caps |
| **口交** (Fellatio) | Attack power, speed, chain caps for this pose |
| **背榨** (Rear mount) | The `Osiri` pose — this mechanism is called **索取** (demand) here |
| **正骑** (Riding) | The `Sit` pose — called **榨取** (drain); also binding kiss and the Manman zone |
| **换装** (Costume) | Outfit and parts |
| **系统** (System) | Caps, diagnostics, snapshots |
| **预设** (Presets) | Save / apply / overwrite / delete configuration snapshots |
| **关于** (About) | Repository, bilibili, feedback address |

> **Three poses, three names for the same mechanism**: fellatio is 吸取 (absorb),
> rear mount is 索取 (demand), riding is 榨取 (drain). The panel changes wording per tab.

### 4.1 Rates — scale every change as it happens

The core feature. Each rate scales the *amount* of a change, at the moment it happens.

| Rate | 100% (default) | At 0% |
| --- | --- | --- |
| **HP down rate** | Damage as shipped | **HP never drops** |
| **HP recovery rate** | Vanilla healing | Burgers heal nothing |
| **Ecstasy rise rate** | Normal accumulation | **Ecstasy never rises** (equivalent to never being drained) |
| **Ecstasy fall rate** | Normal decay | Ecstasy never decays |

Above 100% amplifies (200% = double damage).

This is implemented as **Harmony prefix patches** on `PlayerControl.HPChange`,
`EcstasyChange`, `ECstasyReset`, `HPGaugeChangeValue` and `EcstasyGaugeChangePercent` —
the argument is scaled **before the method body runs**, so the game's own events and the
gauge UI stay consistent. Nothing is forced after the fact.

### 4.2 Countering the cap drain

The game permanently lowers your caps as you get drained:

```
drained  -> HPGaugeChangePercent(-3~5%)      -> maxHP drops, each time
         -> EcstasyGaugeChangePercent(-1~5%) -> maxEcstasy drops, each time
burger   -> healing = maxHP x recovery%      <- healing is a percentage of the CAP
DLC on, overflow -> HPGaugeChangePercent(+)  -> caps rise back
```

So the more you are drained, the harder healing becomes. Countermeasures:

| Control | Effect |
| --- | --- |
| **Lock HP cap / Lock ecstasy cap** | Snaps back to the baseline the moment it is reduced — writes the field directly, no percentage compensation, so it cannot drift |
| **HP / ecstasy cap target** | An **absolute** target; approached smoothly each frame. 0 = disabled |
| **Approach speed** | Points per second — lower is smoother |
| **x1.5 / x2 / Reset** | Shortcuts for setting the target |

> **Why a target instead of a percentage**: early versions applied a percentage on every
> slider change, so dragging **expanded exponentially** to hundreds of thousands and
> stuttered. Now the slider only sets a target and every frame converges under control.
> There is also a hard ceiling of 20000.

### 4.3 Player tab

| Control | Effect |
| --- | --- |
| **Quick toggles** | God mode, no-ecstasy-rise, lock caps — combinations of the rates above |
| **Burger stacks** | How many layers a burger restores (see 4.9) |
| **Ecstasy tremor** | See 4.4 |
| **Ecstasy adaptation** | See 4.5 |
| **Drain chain caps** | Maximum consecutive drains, per pose and per mode |
| **Target caps** | Absolute HP / ecstasy caps, smoothly approached |

### 4.4 Ecstasy tremor — decaying sine wave

While ecstasy accumulates, a random tremor may fire. Five profiles:

| # | Profile | Character |
| --- | --- | --- |
| 1 | 顿挫 (stutter) | Short square wave — feels like catching, at high speed |
| 2 | 痉挛 (spasm) | High-frequency small jitter |
| 3 | 深陷 (sink) | Long, deep — one drop, hold, slow return |
| 4 | 迟疑 (hesitate) | Two hesitations — moves then pulls back |
| 5 | 潮汐 (tide) | Long and short combined |

Press **R** to steady the current tremor.

| Control | Effect |
| --- | --- |
| **Tremor chance** | Probability per accumulation |
| **Tremor amount** | Peak-to-peak amplitude |
| **Tremor duration** | Length in seconds |
| **Tremor profile weights** | Which of the five are used |

### 4.5 Ecstasy adaptation — temporary, strictly restored

After a tremor ends, the amplitude is temporarily adjusted. Everything here is
**temporary and strictly restored when it ends** — the code snapshots the value and puts
it back, it does not rely on drift.

| Control | Effect |
| --- | --- |
| **Safety gate** | Refuses to apply if ecstasy can never reach the cap — otherwise the drain loop never terminates |
| **Amplitude window** | How the post-tremor amplitude is adjusted |
| **Restore check** | Verifies the original value came back |

### 4.6 Drain chain

| Control | Effect |
| --- | --- |
| **Chain max (normal / demand)** | Maximum consecutive drains, separately for normal and demand mode |
| **Ecstasy gain per drain** | How much ecstasy each drain adds |
| **Gain cap / soft cap** | Limits on the per-chain gain |
| **Chain wobble** | Small fluctuation during a chain |

**Only activities inside demand/drain mode count.** This is an invariant of the game's
state machine, not a mod restriction — see the engineering notes.

### 4.7 Afterglow

A state after a drain chain ends. Controls cover how long it lasts, how it scales, and
whether it clears the remaining urge.

### 4.8 Binding kiss (riding pose)

| Control | Effect |
| --- | --- |
| **Kiss speed** | Independent speed for entering the kiss — this is NOT the same as triggering a drain chain |
| **Kiss acceleration** | Whether and how fast the kiss speeds up |
| **Layer playback fallback** | Some animations are only reachable through the direct layer `Play`, not the mixer — the fallback covers that |

### 4.9 Manman zone (riding pose)

A hit area symmetric with the spanking one: it raises the drain urge and gives the
sitting animation a speed impulse. It is created by the plugin, not by the game
(`HitArea_Manman_By_Plugins`), and it uses the same visualisation logic as the game's own
hit areas.

| Control | Effect |
| --- | --- |
| **Enable** | Turns the zone on |
| **Urge gain** | Drain urge added per touch |
| **Speed impulse** | Impulse given to the sitting animation |
| **Position / size** | Where the zone sits, in model-relative coordinates |
| **Highlight** | Shows the zone using the same highlight as other hit areas |

### 4.10 Burger stacks

Explains why burgers are as large as they are: a burger's healing is a percentage of
`maxHP`, and the stack count multiplies it. Changing the stack count changes the
effective healing dramatically once caps are at their defaults.

### 4.11 Presets

The **预设** tab saves the entire configuration as a named snapshot under
`BepInEx/config/nesarf.burgershop.modder.presets/`.

- **Save** — writes every config entry as a snapshot
- **Apply** — overwrites the current settings; a timestamped backup of the current state
  is written first, and the panel tells you the file name
- **Overwrite** — re-saves an existing preset, backing up the old one
- **Delete** — renames the file to `.deleted-<timestamp>` rather than removing it

Snapshots are generic: they enumerate every defined config entry, so parameters added in
future versions are included automatically.

### 4.12 About

Repository, bilibili, feedback address. The 打开 button opens the system browser; the
email row only offers copy, because `mailto:` handlers are unreliable.

## 5. Restoring the game

Three options, in increasing order of thoroughness:

1. **Uninstall** via the installer — removes exactly what it installed (by manifest)
2. **`卸载还原.ps1`** in the game folder — same thing as a standalone script
3. **Manual** — delete `BepInEx\`, `winhttp.dll`, `doorstop_config.ini`,
   `.doorstop_version`, `burger-shop-mod.installed`, and the two executables

The game's own files are never modified, so there is nothing else to restore.
**Your settings are in `BepInEx\config\`, so they go with it** — copy that folder out first
if you want to keep them.

## 6. About "uncensoring"

**Audited, conclusion: this game does not support a switchable uncensor.**

The game ships its art already decensored. There is no mosaic layer to toggle — the
renderer draws the shipped textures directly. Drawing something else would mean authoring
replacement art, which is a different project.

There *is* one related bug, documented in the engineering notes: the tights (stockings)
fail to display for a specific reason — an index bug in the game itself.

## 7. Command channel

A file-based channel for driving the game from a script, without touching the keyboard
or mouse. Write a line to `BepInEx/l2d_dump/cmd/in.txt` and read the reply from `out.txt`.

Full command list is in the Chinese manual's section 六·补. The commands most useful for
automation:

| Command | Effect |
| --- | --- |
| `set <Name> <value>` | Set a config entry; for the three-pose parameters it sets all three |
| `tab <n>` | Switch the panel tab |
| `tabshot <n> <name>` | Switch tab, reset scroll, capture a screenshot plus the panel rect |
| `scroll <y>` | Set the panel scroll position |
| `preset list / save / apply / del <name>` | Manage presets |
| `about on / off` | Expand or collapse the About tab |
| `bindings` | Dump the method→class binding table |

This exists because the mod patches the game by method name, and a wrong class makes a
patch fail **silently**. The command channel makes that observable.

## 8. Technical notes

- **Unity 2022.1.24f1, Mono** — not IL2CPP, which is what makes the BepInEx 5 route work
- **Two animation playback paths** — mixers (`*.State`) and direct layer `Play`
  (`*.CurrentState`). Speed logic has to cover both
- **Mouse and touch are different paths** — the mouse reads a static field
  (`Live2D_HitAreaCheck.mousePointing`), touch uses a method return value
- **Harmony patches a class, not a method name** — the same method name can exist on
  different classes; patching the wrong one fails silently
- **Config has two writers** — the in-game panel and the external editor. A revision
  counter plus a lock means they merge instead of clobbering each other
- **`_demandMode` being true is not the same as "currently in demand mode"** — use the
  state helpers, not the raw flag
- **Assembly name vs release asset name** — the plugin's assembly name contains
  mathematical symbols; release assets must be ASCII, so they differ deliberately

The full engineering log — symptom, root cause, fix, lesson, for every one of them — is
in [`ENGINEERING-NOTES.md`](ENGINEERING-NOTES.md) (Chinese).
